# Files that MUST be byte-identical across quasar-project-template and every project descended
# from it. Checked deterministically by audit-template-divergence.ts (audit:template-divergence),
# which runs in each project's compliance chain and WARNS when a listed file has forked.
#
# WHY THIS EXISTS
#
# The template and its flagship product (Weaver) forked on scripts/audit-sast.ts and nobody
# caught it: the template was fixed, Weaver kept the broken copy, and the only sync tooling was
# a sonnet agent someone had to remember to run before a release, whose content check read "the
# first 20 lines". A fork deep in a rules array is invisible to that. This is the deterministic
# backstop that a human does not have to remember: it runs every push.
#
# WHY THE LIST IS SHORT, AND MUST STAY SHORT
#
# A file belongs here ONLY if it is genuinely meant to be the SAME everywhere — a shared guard
# or a shared contract — NOT a script projects legitimately extend. audit-sast.ts is the
# cautionary case: Weaver correctly adds 9 product-specific security rules to it, so byte-
# identity is the wrong invariant for the script itself. What must not fork is the CONTRACT its
# secret rules are held to — the corpus below. Pin the contract, not the implementation, and
# each project's own self-test keeps its (extended) rules honest against the shared spec.
#
# Divergence WARNS, never fails: which side is authoritative (template moved, or project has a
# fix to promote) is a human call, and a hard fail would break a project's CI every time the
# template advanced. The warning makes the fork loud; a human reconciles it.
#
# Paths are relative to the repository root. Lines starting with # and blank lines are ignored.

# against a different spec than the rest of the portfolio — the guarantee silently differs.

# The licence-header guard. Its LOGIC must be identical everywhere — it is what stops a copied file
# carrying another product's licence, which is how eight Gantry files came to claim AGPL/BSL in a
# proprietary product. Its own HEADER, by contrast, must differ per repo (the template is
# licence-blank; Gantry is proprietary), so audit-template-divergence.ts normalises the licence line
# out of the comparison. This entry is why that exemption exists rather than being speculative: it is
# the first shared file whose header is legitimately per-repo.
#
# NOT listed, deliberately: verify-push-gates.ts. Its logic is shared but its docblock is genuinely
# project-specific (the template's hook gates a narrower chain than test:prepush, for a reason that
# holds only there). Pin the contract, not every file that happens to be similar.
code/scripts/verify-license-headers.ts

# The Docker-first E2E contract. The policy is portfolio-wide (no bare Playwright runner; a browser

# guarantee than everyone else. The checker is pinned with it because nothing here is
# project-specific — unlike audit-sast.ts, which projects legitimately extend with product rules.
#
# Added 2026-08-12. Until then the rule existed only in Gantry, so the template and every other
# descendant had no commit-time guard on a policy all of them are subject to.
code/scripts/fixtures/e2e-docker-only-corpus.txt
code/scripts/verify-e2e-docker-only.ts

# The auditor-contract checker. Its LOGIC is portfolio-wide by definition — it enforces FORGE-41,
# the standard that every auditor must be able to demonstrate it fails — so a repo running a forked
# copy would be holding its auditors to a different contract than everyone else, which is the exact
# class this file exists to catch. Its MANIFEST is deliberately NOT listed: auditor sets differ per
# repo (Weaver 85, template 32, Gantry 19), so scripts/data/auditor-contracts.json is a per-repo
# declaration, the same split as verify-license-headers.ts against verify-legal-ip.ts.
code/scripts/verify-auditor-contracts.ts

# The rule-contract checker — third in the FORGE-36 / FORGE-41 line, and shared for exactly the
# reason above: "a rule that cannot fail is a suggestion" is a portfolio standard, so a forked copy
# would hold one repo's rules to a weaker contract than the rest. Its MANIFEST is per-repo for the
# same reason auditor-contracts.json is (weaver 25 rules, gantry 21, qepton 15, dotclaude 18), and
# the universe is DERIVED from each repo's own .engram.yaml rules: block rather than restated here.
# Requires js-yaml (declared in weaver; a consuming repo needs it before adopting this file).
code/scripts/verify-rule-contracts.ts

# The hook meta-auditor. Built in Gantry 2026-08-12 after two of six hook pairs were found forked —
# one of them the guard that actually loads for every `code/` session, carrying a naive grep that
# blocked innocent commit messages. It replaced a one-command stub (`block-dangerous.sh
# --self-test`) that tested one implementation of one hook and said nothing about whether the hook a
# session LOADS is that implementation.
#
# Shared because all three legs are derived, not declared: settings files, hook trees and the
# self-test target all come from `git ls-files`, so it fits any layout — this repo keeps root hooks
# under core/ and stack/, Weaver keeps them flat. The one hardcoded path it originally carried
# (.claude/hooks/core/block-dangerous.sh) was the only thing that would have forked it, and is now
# derived from the wiring — which also made it strictly stronger, since a repo with the guard in two
# trees now self-tests BOTH.
code/scripts/verify-hooks.ts

# The port-block checker (FORGE-43). Portfolio-wide by definition: it enforces that a repo names
# only ports inside its OWN block, and the whole point of a block scheme is that every product
# obeys it. Product-agnostic by construction — it reads productName from package.json and parses
# the blocks out of docs/development/PORT-ALLOCATION.md, so the file is byte-identical everywhere
# and a scaffolded project needs to edit nothing.
#
# The template ships it deliberately even though a fresh scaffold has no blocks yet: it reports
# NOT YET CONFIGURED rather than a green tick, which is what stops a new project inheriting a
# silent pass. That distinction was found BY putting it in the template — in weaver the table is
# populated, so the vacuous path never ran.
code/scripts/verify-port-allocation.ts
