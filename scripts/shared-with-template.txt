# Files that MUST be byte-identical across quasar-project-template and every project descended
# from it. Checked deterministically by audit-template-divergence.ts (audit:template-divergence),
# which runs in each project's compliance chain and WARNS when a listed file has forked.
#
# WHY THIS EXISTS
#
# The template and its flagship product (Weaver) forked on scripts/audit-sast.ts and nobody
# caught it: the template was fixed, Weaver kept the broken copy, and the only sync tooling was
# a sonnet agent someone had to remember to run before a release, whose content check read "the
# first 20 lines". A fork deep in a rules array is invisible to that. This is the deterministic
# backstop that a human does not have to remember: it runs every push.
#
# WHY THE LIST IS SHORT, AND MUST STAY SHORT
#
# A file belongs here ONLY if it is genuinely meant to be the SAME everywhere — a shared guard
# or a shared contract — NOT a script projects legitimately extend. audit-sast.ts is the
# cautionary case: Weaver correctly adds 9 product-specific security rules to it, so byte-
# identity is the wrong invariant for the script itself. What must not fork is the CONTRACT its
# secret rules are held to — the corpus below. Pin the contract, not the implementation, and
# each project's own self-test keeps its (extended) rules honest against the shared spec.
#
# Divergence WARNS, never fails: which side is authoritative (template moved, or project has a
# fix to promote) is a human call, and a hard fail would break a project's CI every time the
# template advanced. The warning makes the fork loud; a human reconciles it.
#
# Paths are relative to the repository root. Lines starting with # and blank lines are ignored.

# The port-block checker (FORGE-43). Portfolio-wide by definition: it enforces that a repo names
# only ports inside its OWN block, and the whole point of a block scheme is that every product
# obeys it. Product-agnostic by construction — it reads productName from package.json and parses
# the blocks out of docs/development/PORT-ALLOCATION.md, so the file is byte-identical everywhere

#
# The template ships it deliberately even though a fresh scaffold has no blocks yet: it reports
# NOT YET CONFIGURED rather than a green tick, which is what stops a new project inheriting a
# silent pass. That distinction was found BY putting it in the template — in weaver the table is
# populated, so the vacuous path never ran.

# The working-tree ownership guard and its provisioning half. The E2E harness bind-mounts the repo,
# so a container running as root writes root-owned files into the developer's tree and the next
# `quasar dev` dies with EACCES — measured in the template (28 paths, dev server would not start)
# and in weaver (173, under dist/). Portfolio-wide by construction: it RECOVERS the uid variable
# from each repo's own docker-compose.yml rather than assuming a name, which is what let it hold
# weaver to the same invariant while weaver still called it E2E_UID. All four now use HOST_UID —
# the recovery stays because assuming a name is what makes a shared checker un-shareable. A forked
# copy would let one repo's containers keep writing as root while reporting green.

# The shared MCP base, and the guard that keeps it shared-able.
#
# The portfolio ran seven independent copies of codebase-mcp. A byte-comparison said 9 of 30 tool
# files were "identical everywhere" — which reads as a core waiting to be extracted, and was not.
# They were identical because Gantry had inherited WEAVER'S DATA verbatim: service-architecture.ts
# hardcoded an initializationOrder naming vmRegistry / ImageManager / Provisioner, compliance-scripts.ts
# hardcoded Weaver's audit catalogue, and websocket-conventions.ts hardcoded /ws/status and
# verifyWsToken(). Pinning those three byte-identical would have ENFORCED one product's data on every
# other product, permanently. Sameness produced by unexamined copying is indistinguishable from
# sameness produced by good design, and only the second kind belongs on this list.
#
# So only the genuinely product-NEUTRAL half is pinned: five tools that derive everything they return
# from the repo they are pointed at, plus the one shared utility. audit:mcp-base-neutral is what keeps
# it that way — it fails if a base file names a product, if a product re-forks the file reader, or if a
# product shadows a base tool with a local copy. All three legs are negative-tested.
#
# The utility is on this list for a measured reason, not a theoretical one: Gantry's private copy was
# missing listFilesRecursive entirely, so its getProjectRules read .claude/rules with a FLAT reader and
# returned 0 of 15 nested rule files — the always-loaded core/ set, absent with no error. The template
# and Weaver both had the fix. Nothing compared the three copies. Now something does.
code/scripts/verify-mcp-base-neutral.ts
