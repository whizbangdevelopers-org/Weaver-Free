# Regression corpus for the `hardcoded-secret` / `known-secret-format` rules in
# scripts/audit-sast.ts. Read and asserted by the auditor ON EVERY RUN — if any MUST-CATCH
# line stops being caught, or any MUST-IGNORE line starts being flagged, the auditor fails
# before it scans anything.
#
# WHY THIS EXISTS
#
# The previous `hardcoded-secret` rule sat in the compliance chain, was reported green, and
# could not see a single real credential. It was measured against the passwords found live in
# the DemoCRM webroot in July 2026 — served to the open internet — and missed every one, for
# six independent reasons (documented in audit-sast.ts). Nobody noticed, because a rule with
# no test only tells you it found nothing; it never tells you it CANNOT find anything.
#
# The values below are SYNTHETIC. They are not, and never were, real credentials — they carry
# the SHAPES that defeated the old rule (a 14-character alphanumeric password; a password
# ending in punctuation; camelCase and snake_case names; an XML attribute pair), which is what
# the regression is actually about. Do not replace them with real ones: a dead credential in a
# fixture is still a credential in source, and these rules would rightly flag it.
#
# Format:  CATCH <line>   — the rule MUST report this
#          IGNORE <line>  — the rule MUST NOT report this
# Blank lines and #-comments are skipped.

# --- shapes the old rule was blind to -----------------------------------------------------
# 14 chars, alphanumeric: under the old 20-char minimum
CATCH $prodPassword = 'q7Xm2Kd9Lp4Rt1';
# member access: '->' was not an accepted boundary
CATCH $this->crm_password = 'q7Xm2Kd9Lp4Rt1';
# quoted array key, PHP fat arrow
CATCH $cfg = ['password' => 'q7Xm2Kd9Lp4Rt1'];
# trailing '//' comment: the old rule skipped ANY line containing '//'
CATCH $withNote = ['password' => 'q7Xm2Kd9Lp4Rt1']; // prod
# punctuation in the value: '!' was outside the old character class
CATCH $testPass = 'SynthDB_2026_Secret!';
# XML/env attribute pair — .xml was not even scanned
CATCH <env name="TEST_DB_PASS" value="SynthDB_2026_Secret!"/>
# camelCase and SCREAMING_CASE names
CATCH const apiKey = 'a9F2kQ7xZ1mB4nR8'
CATCH DATABASE_PASSWORD="hX3pW9qL2vT6yC1s"

# --- provider token formats, matched on shape alone ---------------------------------------
CATCH const k = 'AKIA1234567890ABCDEF'
CATCH const g = 'ghp_abcdefghijklmnopqrstuvwxyz0123456789'
CATCH const a = 'sk-ant-api03-abcdefghijklmnopqrstuvwxyz'

# --- must stay quiet: flagging these is how an auditor loses its authority -----------------
# UI labels
IGNORE $label_password = "Password";
IGNORE const ariaLabelPassword = "Enter password"
# translations — prose in any alphabet is not a secret
IGNORE $lang = ['password' => 'Contraseña'];
IGNORE $lang = ['new_password' => 'New Password'];
# templates: committing these is the CORRECT behaviour
IGNORE $tpl = ['password' => 'CHANGE_ME'];
IGNORE $tpl = ['password' => '<YOUR_PASSWORD>'];
# throwaway app fixture logins, not credentials
IGNORE $fixture = ['username' => 'testadmin', 'password' => 'test_pass'];
# *_FILE names a LOCATION, not a secret — this is the sops-nix convention and the whole point
IGNORE "ENGRAM_COGNEE_PASSWORD_FILE": "/run/secrets/engram-cognee-password"
IGNORE DB_PASSWORD_FILE=/run/secrets/db-password

# --- shell expansions are not literals (added 2026-08-10) ---------------------------------
# A per-run random value: the assignment is exactly the shape of a hardcoded secret, and the
# value is generated at runtime. Flagging it taught authors to reword rather than to stop
# hardcoding, which is how an auditor loses its authority.
IGNORE LICENSE_HMAC_SECRET="$(head -c 32 /dev/urandom | base64 | tr -d '\n')"
IGNORE DB_PASSWORD="$(vault read -field=pw secret/db)"
IGNORE API_TOKEN=`cat /run/secrets/token`
# Passing an already-resolved variable through to a child process.
IGNORE LICENSE_HMAC_SECRET="$LICENSE_HMAC_SECRET"
IGNORE DB_PASSWORD=${DB_PASSWORD}
# ...but a literal that merely CONTAINS a dollar sign is still a literal, and still a leak.
CATCH DB_PASSWORD="pa$$w0rdLiteral99"
CATCH $cfg = ['password' => 'Str0ng$Pass!2026'];

# --- a constant holding the NAME of an env var is a POINTER, not a credential (2026-08-27) ---
# Same class as PASSWORD_FILE=/run/secrets/… above: this is what a hardcoded credential is
# replaced BY, so flagging it tells an author that doing the right thing is a violation.
IGNORE hardcoded-secret const TOKEN_ENV = 'APP_GITHUB_TOKEN'
IGNORE hardcoded-secret const SECRET_VAR_NAME = "APP_SESSION_SECRET"
# The near-miss in the other direction MUST still be caught: the exemption is on the value being
# an identifier, so a real token assigned to the same-shaped constant is not exempt.
CATCH hardcoded-secret const TOKEN_ENV = 'ghp_0123456789abcdefghijklmnop'
CATCH hardcoded-secret const PASSWORD_ENV = 'hunter2-real-password'
